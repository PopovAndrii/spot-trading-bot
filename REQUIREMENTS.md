6 при заходе на страницу настроек текущей торговли блокируются на SpinBox кнопка минус (если значение больше минимального эта кнопка должна быть разблокирована)
  6.1 Причина: пакет пересчитывает state кнопок только на своих событиях, а приложение ставит value напрямую (el.value=...) без change → "минус" остаётся заблокированным с инициализации (value=min). Решение: ui/spinboxSync.js — syncSpinBoxButtons() повторяет логику state() (минус off при value<=min, плюс off при value>=max) без событий, чтобы не триггерить каскад пересчёта таблицы. Вызывается после установки значений в LoadDataFromFileCalculator.#fillInData и SetStrategy.#setSettings.
7 во время работы робота сделать блокировку всех кнопок установки параметров (кроме старт и рестарт переключателя)
  7.1 Раньше strategy ButtonGroup и SpinBox +/- не блокировались (значения можно было менять). Решение: утилит-класс .params-locked (pointer-events:none + opacity .55) навешивается в SpotWS.#btnRule на .UIbg (выбор стратегии) и #group-spinbox (спинбоксы + select прогрессии). Calculate/Save/Cancel-all блокируются как раньше. Start и Restart-переключатель остаются доступны. Срабатывает и при старте, и при подхвате running-цикла после перезагрузки.
  7.2 Фикс: блокировка не снималась после падения/рестарта сервера (событие stop не приходило). spotStatus сделан авторитетным в обе стороны — при data!=true вызывается #btnRule(false) (разблокировка + сброс interval). Снятие застрявшей блокировки — reload страницы.
8 Проверить вебсокеты нет ли дублей.
  8.1 Браузер↔сервер: дублей нет (реконнект заменяет ws, клиенты в Set, ts-листенеры 1 раз на символ, один timerSender на символ). Binance stream: singleton по символу, дублей инстансов нет. Найден латентный баг: streamAPI.on('message') навешивался при каждом start() на singleton → стек слушателей/дубли price. Решение: streamAPI.removeAllListeners('message') перед привязкой в start() (jsonTimerSender.js).
9 При переходах по страницам происходит вспышка темы. с белой на черную. Предложить решение.
  9.1 Причина: Theme.js (ES-модуль) ставит data-theme после парсинга DOM → FOUC. Решение: синхронный inline-скрипт в начале <head> ставит data-theme='dark' из localStorage ДО первой отрисовки. Theme.js по-прежнему управляет переключателем/иконкой.
10 ./src/lib/job.js предложить решение с частично исполнным ордером. Это сверх ответственный момент. Ситуация: ордер продажи исполнился частично и цена пошла вниз на следующий страховочный ордер который сработал. получается необходим отменить частичную продажу и прибавить эту сумму к следующему ордеру продажи. Одновременно в секции ./src/data/ нужно добавить к конкретному ордеру новую сумму так как значения пресчитываются только до старта.

### Найденные проблемы (из анализа п.1)
11 `#jobItaretor` вызывается без await в readLoop() — следующий тик планируется не дожидаясь завершения. При медленных ответах Binance итерации накладываются → гонки и параллельная запись одного JSON-файла. (jsonTimerSender.js:160)
12 Потеря состояния при рестарте СЕРВЕРА (pm2/падение). running[]/timerSenders/потоки — в памяти. Ордера на Binance остаются висеть, бот молча стоит. (связано с п.2)
13 Дубли слушателей streamAPI.on('message') — добавляются при каждом start() на singleton-инстансе StreamAPI (утечка EventEmitter). (связано с п.8, jsonTimerSender.js:201)
14 Логический баг: `state.NEW ? state.NEW : state.PARTIALLY_FILLED` — 'NEW' всегда truthy, ветка PARTIALLY_FILLED недостижима. (job.js:84, :231)
15 Нет блокировки записи файла: роут /calculator/save и цикл бота пишут один файл. Сохранение из UI во время работы может повредить данные. (смягчается п.7)
16 WebSocket не проверяет авторизацию — start/stop торговлей доступны без сессии. (безопасность для продакшена)
17 Мёртвый индикатор `#output` ".."connect в футере (его никто не обновляет). (закрывается п.4-5)
18 Рассинхрон стратегии при Start: можно запустить LONG на SHORT-файле (и наоборот) → job-логика идёт не в ту сторону → ложный DONE → cancelOpenOrders → краш стрима. Триггер был misclick (Long вместо Short).
  18.1 РЕШЕНО (клиент). SetStrategy.getStrategy() теперь читает отмеченный радио input[name=strategy] (единый источник истины, синхронен и с кликом, и с загрузкой из файла). В SpotWS перед start — гард: если выбранная стратегия ≠ getStrategyName() сохранённого цикла → блок + danger-уведомление, старт не отправляется.
  18.2 ГАРД УБРАН по просьбе пользователя (создавал трение). Реальная причина блокировки в отладке: loadDataFromFileCalculator.strategyName устаревал (файл читается только при загрузке/работе), и гард сравнивал свежий выбор со старым файловым значением. Откатил к оригиналу: гард удалён из SpotWS.btnClickHandler, getStrategy() снова возвращает this.strategyName, autocomplete убран. Start работает как до моих правок. Изменения вносились только через Edit (без git-откатов).
19 РИСК (НЕ решено, по решению пользователя): StreamAPI.stop() роняет процесс (unhandled 'error'), если закрыть ещё не открытый (CONNECTING) сокет — removeAllListeners() снимает обработчик error, затем ws.close() эмитит error. Фикс: noop error-обработчик + terminate() для CONNECTING. Оставлено как известный риск, т.к. ложный путь к нему закрыт гардом 18.1.
